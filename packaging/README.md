# Windows installer and release

The Windows build creates a complete `dist/ZomboidSorter/` onedir application, then Inno Setup wraps that folder in a per-user installer. Keep the full onedir tree together. Setup offers standard and portable data modes. Standard mode keeps app data in `%APPDATA%` and HKCU; portable mode keeps it in `data/` beside the app and requires a writable destination folder. The installer remembers the previous mode on upgrades. Changing modes requires an interactive install, warns that the old data remains in place, and begins using the selected mode's separate data folder; silent cross-mode upgrades are refused. Mod Packs can be exported/imported between modes, while settings are not migrated. The installer offers Start menu and desktop shortcuts as optional tasks. Upgrades and uninstall do not delete user data or game-list backups.

## Local build

Use Windows 11/10 x64, Python 3.14+, and Inno Setup 6. The release workflow builds with CPython 3.14 and uses the package versions in `constraints-windows.txt` with Inno Setup 6.7.1.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev,windows]" -c packaging\constraints-windows.txt
$env:PYTHONPATH = (Join-Path (Get-Location) 'src')
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\ruff.exe check src tests
.\.venv\Scripts\ruff.exe format --check src tests
.\packaging\build_installer.ps1
```

This produces `dist/installer/ZomboidSorter-windows-setup.exe` and a matching `.sha256` file. The app version remains visible in the app window and installer details. The portable choice is included in this installer; there is no separate portable ZIP. `build_windows.ps1` limits DLL search paths during PyInstaller collection, excludes the unused QML asset/plugin tree (this app has no QML views), and removes only the parallel Qt WebEngine **debug** resource copies after checking that the release resource files exist. The remaining Qt and WebEngine runtime files must stay in `_internal`. The installer and Qt window icons use project assets under `assets/`. The build copies the actual bundled interpreter's CPython license, PyInstaller license, and version manifest into the ignored `build/installer_payload/licenses/` staging directory. It generates the Qt attribution appendix from the actual bundled Qt DLL inventory; the complete WebEngine/Chromium appendix remains because QtWebEngineCore is shipped. Expanded HTML notices are staged for the installer only; the PyInstaller app folder in `dist/ZomboidSorter/` stays free of generated license pages. The installer also includes the FDL and applicable license texts, the Inno Setup license, and the written source offer.

## Release

1. Review the source and assets for private data and rights issues. Check the exact PySide6/Qt/WebEngine package versions, their third-party notices, and source availability. Record the reviewer, date, exact bundle version, license/source delivery method, and evidence in `packaging/RELEASE_READY`. The workflow intentionally refuses to publish without it.
2. The pull-request smoke workflow builds the installer and checks standard/portable installation, packaged GUI launch and clean close in both modes, reinstall, cross-mode refusal, uninstall, and app-data preservation on a disposable Windows runner. The rolling-update workflow snapshots and validates the current rolling assets before publishing, then tests the previous stable app's button-to-helper update, verified relaunch, and data preservation. If publication or the end-to-end update smoke fails, it restores the previous assets and tag (or removes the first failed rolling release). The tagged-release workflow tests an upgrade from the previous stable installer when one is available. Separately verify the interactive mode-switch prompt, embedded Workshop page, and updater-launched installer on the verified Windows target. Windows 10 is not a support target; another-PC checks are outside current acceptance scope. Test a real Project Zomboid global config only with an explicit safe test plan.
3. Set `project.version` in `pyproject.toml`, update `src/zomboid_mod_manager/__init__.py`, and commit. Push the commit and a matching `v<version>` tag to the GitHub repository for a stable release. The workflow checks that tag and version agree, runs tests/lint/format, builds the versionless installer, smoke-tests standard and portable install flows, creates a GitHub artifact attestation for the installer and checksum, and creates or updates the tagged GitHub Release. On app changes pushed to `main`, the rolling workflow publishes the latest verified build automatically.
4. Verify the release asset and checksum. ZomboidSorter installers are unsigned, so Windows SmartScreen may say **Unknown publisher** or warn that Windows protected your PC. The README explains how to verify the official download and continue. A checksum match helps detect corruption or an incomplete download; only download installers from the official [Releases page](https://github.com/LookImEcho-Rick/ZomboidSorter/releases). For releases produced by the attestation-enabled workflow, GitHub CLI users can verify the binary's signed build provenance from the download folder:

   ```powershell
   $installer = Get-Item .\ZomboidSorter-windows-setup.exe
   gh attestation verify $installer.FullName --repo LookImEcho-Rick/ZomboidSorter --signer-workflow LookImEcho-Rick/ZomboidSorter/.github/workflows/release-windows.yml
   ```

   This confirms the signed claim for the repository and workflow that produced the exact file. It does not Authenticode-sign the installer or suppress SmartScreen. Releases published before the attestation workflow was added do not have this attestation. See [GitHub artifact attestations](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations) and the [`gh attestation verify` reference](https://cli.github.com/manual/gh_attestation_verify) for verification details.

The CI installer smoke test runs only on disposable GitHub-hosted Windows runners. It seeds app-owned settings and profile sentinels, checks standard and portable installs, launches and closes the packaged app in both modes, verifies an upgrade from the previous stable installer in tagged releases (or reinstall when unavailable), refuses silent cross-mode changes, uninstalls, and checks data preservation. Pull requests run the current-version install/reinstall path without publishing a release. The rolling workflow preserves the prior public update channel and restores it if its post-publication update smoke fails. The v0.1.7 rolling workflow [passed](https://github.com/LookImEcho-Rick/ZomboidSorter/actions/runs/39936416492), exercising the v0.1.6 app's Update button through helper handoff, verified v0.1.7 relaunch, success receipt, portable data preservation, clean close, and uninstall. The [v0.1.7 stable workflow](https://github.com/LookImEcho-Rick/ZomboidSorter/actions/runs/39937388410) passed tests, a v0.1.6 upgrade/install smoke, and provenance attestation; it published the versionless [stable installer](https://github.com/LookImEcho-Rick/ZomboidSorter/releases/tag/v0.1.7). Windows 10 is not a support target; other-PC checks are outside current acceptance scope. Interactive mode-switch prompts and the embedded Workshop page remain uncovered.

The workflow needs repository Actions enabled, a committed `packaging/RELEASE_READY`, and `contents: write` permission for `GITHUB_TOKEN`. The public repository is [LookImEcho-Rick/ZomboidSorter](https://github.com/LookImEcho-Rick/ZomboidSorter). The technical license review record is in `packaging/RELEASE_READY`.

## Third-party redistribution review

The app uses PySide6 6.12.0 and PySide6 WebEngine/PDF 6.12.0.140 (Qt WebEngine 6.140.0 with Chromium 140). Qt for Python is available under LGPL-3.0/GPL-3.0 or a commercial license. Qt WebEngine incorporates Chromium under additional terms, including LGPL-2.1. The install directory permits replacement of compatible dynamic libraries. The installer includes attribution pages for bundled Qt modules, the complete WebEngine/Chromium attribution, GPL/LGPL and runtime/tool license texts, and a written source offer with GitHub Issues as the request channel.

The full pinned source appendices are stored as gzip-compressed files in `licenses/`; the build expands and filters Qt 6.12.0 pages against the runtime DLL inventory. It keeps the complete Qt WebEngine/Chromium inventory. Exact Qt, PySide6, and WebEngine source locations are in `SOURCE_OFFER.md`. Recheck the notice inventory and source links when the Qt pins or bundled Qt modules change. Qt says an upstream link alone may be insufficient, so fulfill requests with the exact corresponding source archive.

Primary references: [Qt for Python licensing](https://doc.qt.io/qtforpython-6/), [Qt LGPL obligations](https://www.qt.io/development/open-source-lgpl-obligations), [Qt WebEngine licensing](https://doc.qt.io/qt-6/qtwebengine-licensing.html), and [Inno Setup AppId/upgrades](https://jrsoftware.org/ishelp/topic_setup_appid.htm). The ZomboidSorter logo is a custom project mark inspired by Project Zomboid's visual style; official game-logo files and RimSort assets are not bundled. The README identifies the app as an unaffiliated fan tool.
