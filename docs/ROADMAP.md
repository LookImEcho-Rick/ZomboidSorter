# Roadmap

Build 42 is the primary target; Build 41 root metadata remains supported. Metadata selection and guarded global, save, and server configuration flows have fixture coverage. No live save or server settings file was written in this work; the isolated Build 42 runtime probe did not reach the fixture mods. Work has proceeded milestone by milestone under `docs/ARCHITECTURE.md`.

| Milestone | Status | Acceptance and limits |
| --- | --- | --- |
| 0 — Research and foundation | Complete | RimSort and PZ research, architecture, license notes, and incremental project structure recorded. No REA used. |
| 1 — Read-only discovery | Complete | Detect Steam/game paths; scan local and Workshop trees; parse root/common/versioned `mod.info`; preserve multiple entries and candidates. Fixture and real-library scans pass. |
| 2 — Mod management | Complete in code; local game check passed | Stage enable/disable/reorder and apply only the verified global `default.txt` with backup/atomic validation. A temporary marker was applied to the local Build 42.21.0 global list, observed in the startup log, then removed; the original file was restored byte-for-byte. No save was opened, and gameplay was not tested. |
| 3 — Profiles | Complete | App-owned ordered Mod ID, Workshop ID, and optional map lists; schema v1/v2 compatibility; import/export, missing IDs, overwrite recovery, and reversible deletion. Map-aware apply asks before replacing the global map list; older profiles preserve current maps. |
| 4 — Dependencies | Complete | Candidate-aware requirements/incompatibilities, missing/inactive references, duplicate IDs, and cycles. Unsupported declarations remain visible rather than guessed. |
| 5 — Sorting | Complete as a proposal; source cross-check added | Deterministic dependency/order-field proposal, persisted explicit before/after rules, stable manual-order ties, and cycle reporting. A Build 42.21 source-derived fixture confirms required mods are proposed before dependents. The isolated runtime probe stopped during Lua initialization before loading fixture mods, so runtime equivalence remains unverified. |
| 6 — Workshop | Complete, read-only | Public item/page metadata, collection import, local/missing-item matching, and profile creation. No subscription, install, or update actions; Steam calls are mock-tested, not live-tested. |

| 8 — Usability | Complete for the initial app and follow-ups | Dark Qt palette, search, multi-selection/bulk controls, internal drag reordering, saved paths/window geometry and ordering rules, asynchronous scanning and diagnostics, and quick Mod Pack save/load in the main workspace. Fixture UI tests and a real-library UI scan pass. |
| 9 — Packaging and reliability | Installer modes, version display, rolling updater, CI smoke checks, and provenance added | The version appears in the app window and installer metadata; the installer filename stays `ZomboidSorter-windows-setup.exe`. Pushed app changes build and smoke-test on GitHub before the verified installer is published to the rolling update channel. The v0.1.8 rolling workflow [passed](https://github.com/LookImEcho-Rick/ZomboidSorter/actions/runs/40040897509), including a real update from the prior stable app, verified relaunch, and portable-data preservation. Windows 10 and manual other-PC checks remain outside the current acceptance scope. |
| 10 — Build-aware metadata | Complete with stated limits | An exact build selects the newest numeric version folder at or below that version; Build 41 uses root metadata, and shared metadata is used when no compatible versioned candidate exists. Build 41/42 family detection is automatic from Steam/game files. A current exact version is used only when `Zomboid/version.txt` is newer than the Steam install update; the field remains manually editable. Detection and selection do not verify mod content compatibility. |
| 11 — Update outcome reporting | Complete; hosted end-to-end update passed | The helper verifies the installed `BUILD_ID` against the downloaded package and writes a receipt. The relaunching app displays success or failure and the failure log path. The hosted v0.1.8 rolling workflow [updated the previous stable app](https://github.com/LookImEcho-Rick/ZomboidSorter/actions/runs/40040897509), displayed the success dialog, consumed the receipt, preserved portable profile/settings data, and closed cleanly. Windows 10 and manual other-PC checks remain outside the current acceptance scope. |
| 12 — Global-list recovery | Complete in code; fixture-validated | Users can list, preview, and explicitly restore a valid timestamped sibling backup. Restore uses the guarded atomic writer and first backs up the current file. Config and UI fixtures cover Mod IDs, maps, encoding, rejection of external paths, confirmation, and staged-state handling. |
| 13 — Save-list import | Complete in code; fixture-validated | Scan only immediate per-save `mods.txt` files, preview their Mod IDs and maps, and import both ordered lists into an app-owned Mod Pack. The list format was checked on a local sample; the app still does not change a save during import. |
| 14 — Sorting source cross-check | Complete in code; fixture-validated | Build 42.21 `ModLoadOrderPanel:isCorrectOrder` checks that each required Mod ID appears before its dependent. A fixture confirms the proposal honors that invariant. `autoSort()` has separate alphabetical insertion behavior, and the isolated runtime probe stopped before fixture mods loaded; full runtime parity is not claimed. |
| 15 — Build detection | Complete in code; fixture-validated | “Use Installed” detects Build 41 from Steam's legacy branch and Build 42 from its Core class marker. A current exact `version.txt` is accepted only when its timestamp is at least as recent as the Steam install update. The target family can still be selected manually, and the exact version field remains editable. |
| 16 — Save-list apply | Complete in code; fixture-validated | Apply staged Mod IDs to one selected immediate save after default-No confirmation. Existing maps are preserved; existing files are backed up, writes use concurrency checks and atomic replacement, and new explicit lists are created exclusively for saves inheriting global settings. Only temporary fixtures were written. |
| 17 — Server settings apply | Complete in code; fixture-validated | Update only `Mods` and `WorkshopItems` in one selected `<Zomboid>/Server/<name>.ini`. Workshop IDs come from unique scanned entries; missing or duplicate Mod IDs block apply. Other lines, including `Map`, are preserved. Only temporary fixtures were written. |
| 18 — Missing Workshop recovery | Complete in code; fixture-validated | Collection import offers a direct page link for selected missing or unavailable numeric IDs, while foreign Steam app rows are excluded. This opens the public page only; it does not subscribe or download. |

## Remaining release gates

- Windows 11 x64 is the current verified target. Windows 10 Home/Pro is not a support target; Microsoft ended support on October 14, 2025. The v0.1.8 rolling workflow verified the update from the previous stable app on a hosted Windows 2022 runner. Manual another-PC checks were not run.
- The Qt/PySide6/WebEngine technical inventory, installer notices, and written source offer are prepared and recorded in `packaging/RELEASE_READY`; keep the offer available and re-review if bundled components or versions change. The original code is GPL-3.0-or-later.
- Releases are intentionally unsigned. Explain the expected SmartScreen warning in the README, and direct users to the official Releases page and the published checksum before running an installer.
- Workshop subscription/download actions and build-specific conflict guarantees remain out of scope until their behavior is independently verified. The release signing/provenance improvements remain separate from these feature changes.
