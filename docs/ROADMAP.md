# Roadmap

Build 42 is the primary target; Build 41 root metadata remains supported. The current launcher manages only the global `Zomboid/mods/default.txt` list. Save-list import and per-save/server configuration features recorded in older milestones were retired to keep the launcher focused on the global list. Those entries are retained as project history. Work has proceeded milestone by milestone under `docs/ARCHITECTURE.md`.

## Current product assessment and next checks

- **Individual local Workshop installation:** Available Mods now offers a native mod catalog with author/subscriber metadata and anonymous installation into the configured local-mod folder. Source fixtures cover discovery, persistence across pack switching, conflict rejection, cancellation and rollback. Hosted installer build/install smoke passed; feature-specific packaged install behavior and in-game behavior remain unverified. Dependency installation and update handling remain manual.

- **Implemented and verified:** read-only discovery, Build-aware metadata selection, staged Available Mods/Active Order editing, dependency proposals, Mod Packs, global-list preflight/apply/backup restore, and read-only diagnostics have fixture and UI coverage. v0.3.0's hosted installer, previous-stable upgrade, rolling update, checksum, and provenance workflows passed.
- **Workshop sign-in persistence:** the embedded browser now uses a persistent Qt WebEngine profile for Steam's session cookies, with storage scoped to standard or portable app data. Focused fixture coverage and a network-free Qt profile smoke passed; real Steam login across launches and packaged behavior remain unverified.
- **Workshop startup and idle cost:** the embedded page still warms after the window appears and the library scan finishes, preserving quick first use. Hidden pages freeze when safe, and after the user has visited the tab they discard after 2 seconds even if Steam keeps the page busy; returning reloads the current URL and retains profile cookies. A local live-page source probe confirmed the renderer exits after discard. The active Steam page still showed occasional 30–45 ms event-loop gaps across GPU, software, CSS, JavaScript, image, and alternate-page probes; a robust active-page fix and packaged behavior remain unverified.
- **Preflight review improvement:** apply and launch now show every active-order finding directly in a scrollable review dialog before an explicit Continue action. The existing writer and backup safeguards are unchanged. The v0.2.6 tagged package and standard/portable install and upgrade smoke passed; no live game was checked.
- **Casual-user interaction review:** double-click adds or removes only the clicked mod, while buttons and context menus act on the selection. Add/Remove wording is consistent, Discover shows the number of mods its bulk-select action will select, and preflight labels the next review step accurately. Compact-window fixture checks cover the shorter button label.
- **Implemented but incomplete:** Build 42 gameplay and full loader behavior remain unverified. Fixture results and metadata warnings cannot establish in-game compatibility. The source UI passed native keyboard-focus review and Qt scale-factor rendering at 150% and 200%; Windows display scaling settings and another-PC behavior remain unverified.
- **Awkward behavior found and fixed:** the live v0.2.4 workspace showed 26 library warnings in Discover without a nearby review action. Discover now exposes a keyboard-accessible **Review** button that opens the first warning or error in Library Diagnostics. Failed refreshes preserve old findings and explain that they remain in use. The clean state hides the action; fixtures cover warning, error, failure, keyboard, and 980×680 behavior. See `docs/PROGRESS.md`.
- **Duplication/complexity:** the changed flow still has one diagnostics text view and one cursor-navigation helper; no duplicate parser, writer, worker, or widget was introduced. The existing active-order **Review** action uses the same navigation helper.
- **Window bounds found and fixed:** a fresh source run at Qt scale factor 2.0 opened mostly off-screen. Startup now bounds initial/restored geometry to the selected screen when the screen can fit the app's minimum. A second live 200% run showed all three panels and the footer; the full fixture suite covers oversized, partially off-screen, and already-valid rectangles. See `docs/PROGRESS.md`.
- **Workspace wording and empty states found and fixed:** the live v0.2.4 workspace showed “Not installed” for Mod IDs absent from the selected scan folders, repeated the idle Details prompt, and produced “1 mod entries” in its summary. The app now explains scan evidence and next steps, and the empty pack manager hides duplicate guidance. The 980×680 source-fixture capture confirmed the panels fit, but the Qt offscreen platform rendered text as missing glyphs, so it does not establish typography. See `docs/PROGRESS.md`.
- **Diagnostics table clipping and silent empty results found and fixed:** a live source run at 1440×900 showed the installed-folder column clipped behind a horizontal scrollbar. The table now fits its primary columns at a normal width, keeps complete cell text in tooltips, and replaces a blank table with recovery guidance when the library is empty or a search has no matches. The build selector and Add/Remove actions now explain their scope and staged effect. See `docs/PROGRESS.md`.
- **Mod Pack and selection continuity improved:** applying a pack now asks before replacing unfinished staging and restores the prior staged list if a later apply step stops. Add/Remove requires a visible selection after Escape clears it, and reports the staged result. A 980×680 rendered fixture exposed clipped build and apply labels; compact labels now fit. See `docs/PROGRESS.md`.
- **Mod Pack verification message corrected:** if a pack write has changed the loaded snapshot but the final reload cannot verify it, the UI keeps the uncertain state visible and asks for a reload instead of claiming the pack was not applied. A disposable file fixture covers that path. See `docs/PROGRESS.md`.
- **Collection import scaling:** Mod ID de-duplication now uses set membership while preserving first-seen order. A synthetic 10,000-ID operation benchmark showed about 240× lower deduplication time; this does not change Workshop matching or establish an end-to-end import speedup. See `docs/PROGRESS.md`.
- **Collection import follow-up (v0.3.1):** receipt-current SteamCMD downloads are reused, new anonymous downloads share a process for batches of up to 200 items, and completed items from partial failures are preserved in the shared cache. The review shows local installation, private download, and saved-pack state separately. Default names avoid accidental collisions. The 220-test suite, Ruff, compilation, and whitespace checks passed; hosted tagged/rolling installer and updater checks passed. Feature-specific live collection validation remains pending. Large-collection speed on a user's machine remains unmeasured.
- **Collection duplicate-ID recovery (rolling follow-up on v0.3.1):** the importer lets users choose which conflicting Workshop item to include, saves the remaining mods under the chosen pack name, and avoids reprocessing the cache after a cancelled conflict prompt. The full 222-test suite, static checks, hosted installer/launch smoke, and previous-stable updater smoke passed. Live Steam collection and game-runtime validation remain unverified.
- **Collection load priority and scan delay (rolling follow-up on v0.3.1):** loading deploys the exact cached pack copy and selects it for matching Mod IDs while preserving other installed files. It reuses the previous Workshop scan instead of rescanning the configured Workshop roots and refreshes local mods only. When launched from ZomboidSorter, a one-time `-modfolders mods,workshop,steam` argument puts local copies before Workshop copies. Focused fixtures validate deployment, app selection, and scan reuse; Steam argument forwarding and live game behavior remain unverified. Multiple duplicates inside the local `Zomboid/mods` root remain ambiguous.
- **Native collection discovery/import:** shared exact-content cache with anonymous SteamCMD download, load-time local deployment, Available Mods re-add workflow, and guarded global apply. No subscriptions change. See the latest progress entry for validation and limitations.
- **Collection review and load follow-up:** imports retain a visible summary and per-item verified progress, stop into a retryable review, block stale links/unavailable items, and identify unreadable Workshop content. Pack loading reuses unchanged ownership-recorded folders with full integrity verification and rollback. A disposable 30-item benchmark measured reloads at 7.91 → 2.72 seconds and a switch retaining half the folders at 4.42 → 1.69 seconds; these are local synthetic timings, not gameplay results. See `docs/PROGRESS.md` for checks and remaining limitations.
- **Next priority:** validate packaged collection and local Workshop install flows against disposable content, then check game runtime where safe. Avoid extra feature work before that verification.

## Remaining release gates

- Windows 11 x64 is the current verified target. Windows 10 Home/Pro is not a support target; Microsoft ended support on October 14, 2025. The v0.1.8 rolling workflow verified the update from the previous stable app on a hosted Windows 2022 runner. Manual another-PC checks were not run.
- The Qt/PySide6/WebEngine technical inventory, installer notices, and written source offer are prepared and recorded in `packaging/RELEASE_READY`; keep the offer available and re-review if bundled components or versions change. The original code is GPL-3.0-or-later.
- Releases are intentionally unsigned. Explain the expected SmartScreen warning in the README, and direct users to the official Releases page and the published checksum before running an installer.
- Subscription-free downloads passed an isolated real SteamCMD probe. Packaged and game-runtime deployment still need validation. Content caches and recovery archives remain local and are never automatically deleted.
