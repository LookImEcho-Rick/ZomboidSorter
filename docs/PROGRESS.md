## Faster collection loading research (2026-10-25)

- The `Preparing collection mod folders: 48/166` label counts distinct folder digests, not bytes or time; folder sizes vary and the progress bar is indeterminate. A new local 30-item/1,920-file/15-MiB synthetic baseline on Python 3.14.7 and NTFS measured 8.172 seconds for first load, 3.487 seconds for reload, and 2.194 seconds for a half-overlap switch (three-run medians; setup excluded).
- The current path validates each full cache item, hashes each contained mod entry, copies new entries through a custom Python file callback, then hashes both the source and staged copy. Research found Python 3.14.7's native Windows `CopyFile2` path and optional ReFS block cloning, but the current callback bypasses it. Recommended next experiment: combine item and subfolder digests in one traversal, copy with a no-overwrite/cancelable native adapter, and retain staged-destination verification and rollback. Hard links would share mutations with the cache and are unsafe.
- Using the user-supplied Project Viewpoint collection as a real workload, Steam currently returns 142 items; the local saved pack matches 141 and contains 166 Mod IDs. On Python 3.14.7/NTFS, one isolated run measured first deployment at 519.490 s, same-pack reload at 193.319 s, and unloading to an empty-content profile at 44.312 s. The first-load copy interval, including post-copy hashes and final commit, occupied 355.25 s; local discovery took 0.28 s. Reload and unload time was repeated integrity hashing. This is one run against the existing 141-item cache, not a median or a live-game test.
- This baseline was superseded by the 2026-10-26 implementation below. The 141-item saved profile is one Workshop item short of the current 142-item collection page; no new downloads or subscriptions were made. Detailed options, limits, and exact sources remain in `docs/research/WORKSHOP_COLLECTION_IMPORT.md`.

## Collection load and unload speed-up (2026-10-26)

- Cache verification and entry digests now share one file traversal per Workshop item. Four workers verify independent items concurrently while preserving profile order and stopping sibling work on failure/cancellation. Windows uses cancelable `CopyFile2` calls with fail-if-exists semantics; four workers copy independent mod folders, and each destination is hashed once against the expected digest. The already-verified source is no longer read a second time after that destination check.
- Added deployment-index schema 2 with device/file IDs and kept schema 1 readable. **Unload Pack** now archives recorded app-owned folders to the transaction recovery directory, leaves global `default.txt` and staged Active Order unchanged, and preserves edited files. It rejects links and unowned/replaced folder roots; when identity matches, it skips reading file bytes. Legacy records without IDs use the full exact-content hash. Normal loading and reactivation still verify exact bytes.
- Benchmark used the same local Project Viewpoint pack and its existing cache (141 Workshop items, 166 Mod IDs, about 2.80 GB across 80,072 files), with a disposable `Zomboid/mods` target on C: NTFS. First deployment improved from **519.490 s** to **195.956 s** (62% faster); same-pack reload improved from **193.319 s** to **89.038 s** (54% faster); unload improved from **44.312 s** to **9.970 s** (78% faster). These are single runs, not medians, and exclude downloads, prompts, global-list apply, game startup, and gameplay. The final first-load run used the four-worker copy cap. No live game files were touched.
- A focused sample confirmed four-worker copy+verification at 13.0 s versus 31.9 s sequential for 10,000 files / 425 MB. Eight workers were only 1.8 s faster than four on the full pre-hash-parallel run, so the final cap remains four. Cache-only verification of all 141 items measured 69.8 s sequential and 36.5 s with four workers.
- Validation: the full suite passed **242 tests with one environment-only skip**, including combined-digest, destination-only verification, legacy-index fallback, fast archive, and UI unload regressions. Ruff check/format, compileall, `pip check`, and `git diff --check` passed. The local Windows bundle and versionless installer compiled. No new dependencies were added. Packaged collection use and real-game checks remain unverified; the optimized first load still takes about 3 minutes on this workload.
